# Indus hold fix (2026-11-02)

Indus put BingeJam **on hold** after the first upload (0.6.0). This note covers why that happened and what changed.

## The two hold reasons

| Indus said | What caused it |
|---|---|
| "The CTA in the app redirects users to download from outside the appstore ecosystem." | The app has its own updater that checks GitHub (`aritraroy02/sync-it-releases`). When a newer version exists, it shows a **Download update** button that opens the APK link on GitHub. Indus doesn't allow downloads from outside its store. |
| "App requests an update immediately after installation." | We uploaded 0.6.0 while GitHub already had 0.6.6. The first launch found the newer version and asked for an update right away. |

The updater asks for updates in three places, and all three point to GitHub:

1. The **Home banner**: "BingeJam X is available" with a **Download update** button.
2. **Settings → About & legal**: the version row checks for updates and opens the GitHub download link.
3. The **update push notification**: the relay announces each release on the FCM topic `updates`, and the app shows "BingeJam X is available".

## What changed

Indus gets its own build with the GitHub updater switched off. The GitHub build behaves exactly as before.

- **`app/build.gradle.kts`**
  - New build-time switch `BuildConfig.SELF_UPDATE`.
  - It's `true` by default (the GitHub build).
  - Building with `-Pstore=indus` sets it to `false`.
- **`UpdateChecker.kt`**
  - New `enabled` flag that reads the switch.
  - `check()` never contacts GitHub when the flag is off, so the Home banner never appears.
- **`PushNotifications.kt`**: when the flag is off, the app doesn't subscribe to the `updates` topic and ignores any update announcement.
- **`SettingsScreen.kt`**: when the flag is off, the version row says "Updates come through the app store you installed from" and isn't tappable.
- **`scripts/release.sh`**
  - The automatic Indus upload now builds the Indus version first: `./gradlew assembleRelease -Pstore=indus`, then `dist/sync-it-indus.apk`.
  - It uploads that file instead of the GitHub APK.
- **`CLAUDE.md`, `store/indus/LISTING.md`**: point to the Indus build.

The Indus APK is signed with the same release key and has the same version (0.6.6, versionCode 16) as the GitHub one. Someone who installed from GitHub can move to the Indus version, or the other way round, without uninstalling.

## Building the Indus APK

```bash
./gradlew assembleRelease -Pstore=indus
cp app/build/outputs/apk/release/app-release.apk dist/sync-it-indus.apk
```

To check a build, look in `app/build/generated/source/buildConfig/release/`: the generated `BuildConfig.java` should contain `SELF_UPDATE = false`.

## Resubmitting

1. In the Indus console, open **Edit Details**.
2. Replace the 0.6.0 APK with `dist/sync-it-indus.apk` (0.6.6).
3. Click **Submit for Final Review**. Suggested note for reviewers: *"Removed the in-app external update link; the app now updates only through Indus. Uploaded the latest version (0.6.6)."*

## Might come up next

Room invites and "Share your profile" send a link to `syncit-watchparty.web.app`. That page offers the GitHub APK to friends who don't have the app. It's a web page, not a button inside the app, so it shouldn't count. If a reviewer flags it anyway, the Indus build can share the Indus store listing link instead.
